Dự án: payment service thanh toán hoá đơn qua cổng đối tác — idempotency, trạng thái chờ xác nhận, circuit breaker, đối soát file

Nói thành tiếng trước khi mở đáp ánNói trôi 45 giây mới là thuộc. Phím t để bấm giờ.

Xây một payment service thanh toán hoá đơn (điện, nước, viễn thông) qua một cổng đối tác giả lập hay chậm và hay lỗi. Mục tiêu: chứng minh bằng test và số đo rằng không có khoản thanh toán trùng, không có khoản nào "mất tích", và service vẫn phục vụ được khi đối tác sập.

Bối cảnh

  • Thời lượng gợi ý: 2–3 cuối tuần.
  • Đối tác giả lập tự viết (Spring Boot hoặc WireMock) có thể cấu hình: độ trễ, tỉ lệ lỗi, timeout mà vẫn xử lý thành công, callback trễ, file đối soát cuối ngày.

Yêu cầu

  • Spring Boot 4 + Java 25, PostgreSQL, Kafka (hoặc chỉ outbox + DB nếu muốn gọn), Docker Compose.
  • API POST /bill-payments bắt buộc Idempotency-Key; GET /bill-payments/{id}.
  • Máy trạng thái: CREATED → SENT → SUCCEEDED | FAILED | PENDING_CONFIRMATION → SUCCEEDED | FAILED.
  • Gọi đối tác bằng HTTP service client: timeout, circuit breaker (Resilience4j), giới hạn đồng thời.
  • Timeout không bao giờ gửi lại mù: job tra cứu trạng thái theo mã tham chiếu.
  • Job đối soát file của đối tác với dữ liệu nội bộ, sinh danh sách lệch.
  • Sự kiện BillPaid phát qua outbox; tracing đầu-cuối.
