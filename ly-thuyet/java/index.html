Lý thuyết, Junior, Spring core & DI, khoảng 6 phút

@Component, @Service, @Repository, @Controller khác nhau thế nào? Khi nào dùng @Bean trong @Configuration, và BeanRegistrar của Spring 7

Câu trả lời tốt nhất

nói trong khoảng 45 giây

Cả bốn đều là stereotype — đều là @Component để component scan tìm và tạo bean. Khác biệt chủ yếu là ý nghĩa và một ít hành vi: @Repository bật dịch exception — lỗi riêng của JDBC/JPA được chuyển thành DataAccessException thống nhất; @Controller/@RestController được Spring MVC nhận diện làm handler; @Service hiện chỉ mang ý nghĩa tầng nghiệp vụ, nhưng giúp đọc code và viết pointcut AOP theo tầng. Tôi dùng @Bean trong @Configuration khi không sửa được lớp (thư viện bên thứ ba như RestClient, ObjectMapper), khi việc tạo cần logic (đọc cấu hình, chọn cài đặt), hoặc cần nhiều bean cùng kiểu với cấu hình khác nhau. proxyBeanMethods = true (mặc định) khiến lớp @Configuration được CGLIB bọc để gọi method @Bean từ method khác vẫn trả cùng singleton; đặt false (chế độ "lite") khởi động nhanh hơn, nhưng gọi chéo sẽ tạo object mới. Spring 7 thêm BeanRegistrar để đăng ký bean bằng code với if/vòng lặp.

Trả lời đầy đủ

Về mặt đăng ký bean, @Service, @Repository, @Controller đều là @Component — component scan tìm thấy và tạo bean như nhau. Khác biệt nằm ở ý nghĩa và một vài hành vi kèm theo: @Repository được Spring dịch exception của tầng dữ liệu sang DataAccessException thống nhất; @Controller được Spring MVC nhận diện để ánh xạ request. @Bean trong lớp @Configuration dùng khi cần tạo bean từ lớp không phải của mình (client của thư viện, RestClient, ObjectMapper cấu hình riêng) hoặc khi việc tạo cần logic. proxyBeanMethods = true (mặc định) khiến các method @Bean gọi lẫn nhau vẫn trả về đúng singleton; đặt false (lite mode) khởi động nhanh hơn khi không có lời gọi chéo.

Người phỏng vấn hỏi câu này để xem bạn có biết điểm khác biệt thật hay chỉ học thuộc rằng chúng "giống nhau". Ý quan trọng: stereotype là cho lớp của mình, @Bean là cho lớp mình không sửa được hoặc cần logic khi tạo. Phần dưới minh hoạ cả hai cách, cách đăng ký bằng code mới của Spring Framework 7, và bảng hành vi thêm của từng chú thích để trả lời nhanh khi bị hỏi dồn.

Hai cách khai báo bean

@Service                                         // lớp của mình -> đánh dấu lớp
class TransferService {
    private final CoreBankingClient core;
    TransferService(CoreBankingClient core) { this.core = core; }
}

@Configuration(proxyBeanMethods = false)
class ClientsConfig {
    @Bean                                        // lớp của thư viện -> @Bean
    RestClient coreBankingRestClient(RestClient.Builder builder, CoreBankingProperties props) {
        return builder.baseUrl(props.baseUrl()).build();
    }

    @Bean
    CoreBankingClient coreBankingClient(RestClient coreBankingRestClient) {   // tham số thay vì gọi method -> an toàn với lite mode
        return new CoreBankingClient(coreBankingRestClient);
    }
}

Đăng ký bằng code (Spring Framework 7)

@Configuration
@Import(PartnerClientsRegistrar.class)
class PartnerConfig { }

class PartnerClientsRegistrar implements BeanRegistrar {
    @Override
    public void register(BeanRegistry registry, Environment env) {
        for (String partner : List.of("napas", "visa", "mastercard")) {
            registry.registerBean(partner + "Client", PartnerClient.class, spec -> spec
                .supplier(ctx -> new PartnerClient(partner, ctx.bean(RestClient.Builder.class))));
        }
    }
}

Thay cho BeanDefinitionRegistryPostProcessor dài dòng; thân thiện với AOT/native image.

Bảng nhanh

Chú thích Hành vi thêm
@Component chỉ là bean
@Service không (ý nghĩa tầng)
@Repository dịch exception persistence
@Controller / @RestController handler MVC / + @ResponseBody
@Configuration chứa @Bean, proxy để giữ singleton (mặc định)

Sẽ bị hỏi tiếp

  • Hai bean cùng kiểu thì inject thế nào? @Qualifier("tên"), @Primary cho mặc định, hoặc inject List<T>/Map<String, T> để lấy tất cả.
  • Component scan quét những đâu? Package của lớp @SpringBootApplication và các package con — lý do lớp này nên nằm ở package gốc.
  • Spring Data repository (interface) không có @Repository vẫn chạy? Có — Spring Data tự tạo cài đặt và đăng ký bean, kèm dịch exception.

Bẫy thường gặp

  • Gọi method @Bean từ method khác với proxyBeanMethods = false — tạo hai object khác nhau.
  • Đặt @SpringBootApplication ở package con — các bean ở package khác không được quét.
  • @Component cho lớp chỉ chứa hàm static tiện ích — không cần bean.

Thực tế trong dự án của tôi

Ngữ cảnh dựng từ backend Spring Boot của các dự án bạn đã tham gia (vai trò chính của bạn là Angular) — ghi rõ phần tự làm và phần chỉ phối hợp. Tình huống điển hình là tình huống hay gặp ở backend ngân hàng, bảo hiểm do app biên soạn để luyện cách kể; số liệu là ví dụ minh hoạ. Chưa làm trực tiếp thì kể là đã tìm hiểu hoặc thử ở dự án luyện tập, đừng nhận là đã làm ở công ty.

Ngữ cảnh: Angular có @Component, @Injectable; Spring có @Component, @Service, @Repository, @Controller.

  • Đã làm: giải thích @Repository dịch exception DB, @Bean dùng khi không sửa được class (thư viện bên thứ ba như RestTemplate).
  • Kết quả: trả lời nhanh, có liên hệ.

Tình huống điển hình: Đội cần dùng một client ký số từ thư viện của đối tác, không sửa được class để thêm @Component. Họ khai báo @Bean trong @Configuration kèm cấu hình chứng thư và timeout. Các lớp truy cập dữ liệu đánh @Repository để lỗi database được dịch sang DataAccessException thống nhất. Với số lượng bean tạo động theo cấu hình (mỗi đối tác một client), Spring 7 có BeanRegistrar thay cho cách đăng ký thủ công cũ.
