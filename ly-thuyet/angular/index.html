== và === khác nhau thế nào? Truthy/falsy và ép kiểu ngầm gây lỗi gì?

Câu trả lời tốt nhất

nói trong khoảng 45 giây

=== so sánh cả kiểu và giá trị, không ép kiểu; == ép kiểu trước khi so sánh theo một bảng luật khó nhớ, nên '' == 0 và null == undefined đều true. Object.is giống === trừ hai điểm: NaN bằng chính nó và +0 khác -0 — signal của Angular dùng đúng phép so sánh này để quyết định có báo thay đổi không. Falsy chỉ có tám giá trị: false, 0, -0, 0n, '', null, undefined, NaN. Lỗi thật hay gặp nhất là if (amount) bỏ qua số tiền 0; nên kiểm tra rõ amount == null hoặc dùng ?? thay ||.

Trả lời đầy đủ

Ba phép so sánh

Biểu thức == === Object.is
0 và '' true false false
null và undefined true false false
NaN và NaN false false true
+0 và -0 true true false
[1] và '1' true false false

Với object, cả ba đều so sánh tham chiếu: {} === {} là false.

Ngoại lệ được chấp nhận của ==

x == null bắt cả null lẫn undefined trong một phép so sánh — nhiều style guide cho phép đúng trường hợp này.

Lỗi thật do ép kiểu

// 1. Số tiền 0 bị coi là "không có"
const fee = input.fee || 10000;   // fee = 0 thành 10000!
const fee2 = input.fee ?? 10000;  // ?? chỉ thay khi null/undefined

// 2. Query param luôn là string
const page = route.snapshot.queryParamMap.get('page'); // '2'
page + 1;                         // '21' chứ không phải 3
Number(page) + 1;                 // 3

// 3. Sắp xếp số mặc định theo chuỗi
[10, 9, 1].sort();                // [1, 10, 9]
[10, 9, 1].sort((a, b) => a - b); // [1, 9, 10]

// 4. Tiền tệ với số thực
0.1 + 0.2 === 0.3;                // false -> tính tiền dùng số nguyên (đồng, xu) hoặc thư viện decimal

Trong Angular

  • signal() và computed() mặc định so sánh bằng Object.is: set lại cùng tham chiếu object → không báo thay đổi. Muốn báo thì tạo object mới hoặc truyền equal tuỳ chỉnh.
  • input.required<number>() với transform: numberAttribute giúp chuyển attribute chuỗi "5" thành số an toàn.

Sẽ bị hỏi tiếp

  • Vì sao typeof null === 'object'? Lỗi lịch sử từ phiên bản đầu của JavaScript, giữ lại để không phá web. Kiểm tra null thì so sánh trực tiếp x === null.
  • So sánh hai object theo nội dung thế nào? Không có sẵn trong ngôn ngữ; viết hàm deep equal hoặc so sánh theo id. Đừng dùng JSON.stringify vì phụ thuộc thứ tự khoá và bỏ undefined.
  • ?? và || khác nhau ở đâu? || thay mọi giá trị falsy; ?? chỉ thay null/undefined. Với số tiền, chuỗi rỗng hợp lệ, cờ false thì phải dùng ??.

Bẫy thường gặp

  • Dùng if (value) để kiểm tra "đã nhập" — 0, '' và false có thể là giá trị hợp lệ.
  • Nghĩ NaN === NaN là true — luôn false; dùng Number.isNaN.
  • Cộng tiền bằng số thực — sai số làm tròn; dùng đơn vị nhỏ nhất dạng số nguyên hoặc thư viện decimal.

Thực tế trong dự án của tôi

Ngữ cảnh dựng từ dự án thật trong CV của bạn — kiểm tra lại chi tiết trước khi dùng. Tình huống điển hình là tình huống hay gặp ở dự án Angular ngân hàng, bảo hiểm do app biên soạn để luyện cách kể; số liệu trong đó là ví dụ minh hoạ. Khi phỏng vấn, chỉ nhận là của mình phần bạn đã thật sự làm; phần còn lại kể là tình huống đã tìm hiểu hoặc tái hiện.

Ngữ cảnh: ngân hàng A — số tiền, tỉ lệ có thể bằng 0; kiểm tra kiểu if (!value) sẽ coi 0 là "chưa nhập".

  • Đã làm: dùng value == null hoặc ?? cho kiểm tra rỗng; bật rule ESLint eqeqeq.
  • Kết quả: hết lỗi bỏ qua giá trị 0.

Tình huống điển hình: Ô tỷ lệ phí bằng 0 bị coi là chưa nhập vì code kiểm tra if (!rate), nên hồ sơ miễn phí bị bắt nhập lại. Đội đổi sang kiểm tra rate == null hoặc dùng ?? thay || cho giá trị mặc định; bật luật ESLint eqeqeq để chặn == trừ trường hợp so với null. Hết lỗi bỏ qua giá trị 0 hợp lệ ở các màn tiền và tỷ lệ.
