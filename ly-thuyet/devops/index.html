.gitignore hoạt động thế nào — quy tắc mẫu, vì sao không tác dụng với file đã được track (git rm --cached), check-ignore, và không để .env, secret lọt vào repo

Câu trả lời tốt nhất

nói trong khoảng 45 giây

.gitignore chỉ có tác dụng với file chưa được track — nó bảo Git "đừng đề xuất add những file này". File đã từng được commit thì Git vẫn theo dõi dù khớp mẫu ignore; muốn ngừng theo dõi phải gỡ khỏi index bằng git rm --cached <file> (file vẫn còn trên đĩa), rồi commit. Mẫu ignore: target/ (thư mục ở mọi cấp), /dist (chỉ ở gốc), *.log, **/tmp, !keep.log (ngoại lệ). Có ba nơi khai báo: .gitignore trong repo (chia sẻ với cả đội), .git/info/exclude (riêng repo trên máy bạn), và file global qua core.excludesFile (rác của IDE, .DS_Store). git check-ignore -v <file> cho biết dòng nào ở file nào đang bỏ qua nó. Với secret: ignore .env, commit .env.example không có giá trị thật — và nhớ ignore không xoá secret đã lỡ commit khỏi lịch sử.

Trả lời đầy đủ

Lý do file đã track không bị ảnh hưởng: Git quyết định theo dõi một file khi nó có trong index. .gitignore chỉ được tham khảo khi Git liệt kê file mới (untracked) hay khi bạn git add .. Một file đã nằm trong index thì mỗi lần sửa nó vẫn hiện là "modified". Sau khi git rm --cached và commit, file biến mất khỏi repo ở commit đó — người khác pull về sẽ bị xoá file đó trên máy họ, nên cần báo trước nếu đó là file cấu hình cá nhân ai cũng có.

Đặt rác của công cụ cá nhân (.idea/, .vscode/ riêng, .DS_Store) vào ignore global thay vì .gitignore của dự án, để file của dự án chỉ chứa thứ thuộc về dự án: output build (dist/, target/, node_modules/), file sinh ra, file môi trường. Ngược lại, đừng ignore lockfile (package-lock.json, file wrapper Maven) — chúng là một phần của build tái lập được.

Ngừng track một file đã commit

echo "application-local.yml" >> .gitignore
git rm --cached src/main/resources/application-local.yml
git commit -m "chore: ngừng track cấu hình local, dùng application-local.example.yml"
git check-ignore -v src/main/resources/application-local.yml
# .gitignore:12:application-local.yml    src/main/resources/application-local.yml

.git/info/exclude không file riêng của bạn trong repo này
core.excludesFile (global) không rác của IDE, hệ điều hành trên mọi repo

Sẽ bị hỏi tiếp

  • git update-index --assume-unchanged có thay được ignore không? Không nên: đó là gợi ý hiệu năng, Git có thể bỏ qua nó; --skip-worktree gần mục đích hơn nhưng dễ gây conflict khó hiểu khi file thay đổi trên remote.
  • Lỡ commit .env có mật khẩu thật thì sao? Đổi mật khẩu ngay — ignore hay xoá ở commit sau không gỡ được khỏi lịch sử; xem Tình huống: khoá API của đối tác thanh toán bị commit lên repo và in ra log CI công khai 6 giờ — phản ứng, đánh giá thiệt hại, ngăn tái diễn.
  • Vì sao !important.log không có tác dụng? Nếu thư mục cha đã bị ignore (logs/), Git không đi vào thư mục đó nên không thấy được ngoại lệ bên trong.

Bẫy thường gặp

  • Tưởng thêm vào .gitignore là file biến khỏi repo — phải git rm --cached.
  • Ignore lockfile — mỗi máy cài một phiên bản phụ thuộc khác nhau.
  • Dựa vào .gitignore để bảo vệ secret — một lần git add -f hay đổi tên file là lọt; cần thêm hook quét secret và push protection.

Thực tế trong dự án của tôi

Ngữ cảnh dựng từ phần hạ tầng của các dự án bạn đã tham gia (vai trò chính của bạn là Angular; hạ tầng thường do team nền tảng sở hữu). Tình huống điển hình là tình huống hay gặp khi vận hành hệ thống ngân hàng, bảo hiểm do app biên soạn để luyện cách kể; số liệu là ví dụ minh hoạ. Chỉ nhận là của mình phần bạn đã thật sự làm; phần khác kể là đã tìm hiểu hoặc tái hiện trong lab.

Ngữ cảnh: các repo Angular ở ngân hàng A và app doanh nghiệp của ngân hàng B đều có .gitignore; cấu hình môi trường (URL API theo môi trường) là chỗ hay bị commit nhầm khi chạy local.

  • Đã làm: tách cấu hình local khỏi repo, dùng file mẫu không chứa giá trị thật; dùng git check-ignore -v khi một file "không chịu" bị ignore.
  • Kết quả: không còn commit lẫn cấu hình máy cá nhân vào merge request.

Tình huống điển hình: Một file cấu hình local chứa URL và tài khoản test của môi trường UAT bị commit nhầm lên nhánh chung. Thêm vào .gitignore không có tác dụng vì file đã được track; đội chạy git rm --cached, thêm file mẫu config.example.json không có giá trị thật, đổi mật khẩu tài khoản test đã lộ, và bật quét secret trong pre-commit lẫn CI. Ba tháng sau không còn file cấu hình nào bị commit nhầm.
