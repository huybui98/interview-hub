Hướng dẫn›Java Spring Boot từ con số 0

Phỏng vấn Java Spring Boot — Senior

60 câu lý thuyết và trade-off level Senior (JVM và concurrency sâu, transaction và nhất quán dữ liệu, bảo mật ngân hàng, Kafka và hệ phân tán, hiệu năng có số đo, kiến trúc và hệ thống ngân hàng, dẫn dắt), 12 câu tình huống sự cố, 5 bài thực hành và 2 dự án; mỗi câu có mức ưu tiên, trả lời ngắn, giải thích sâu, code, bẫy và câu đào tiếp.

Level cuối của bộ câu hỏi đi kèm lộ trình Java Spring Boot từ con số 0 — tương ứng giai đoạn 8–11. Trước đó: Newbie · Junior · Middle.

Ở level Senior, người phỏng vấn hỏi quyết định: bạn chọn gì trong ngữ cảnh này, cái giá là gì, đo thế nào để biết mình đúng, và khi sự cố xảy ra lúc 2 giờ sáng bạn làm gì theo thứ tự nào. Câu trả lời tốt luôn có số đo (p99, số kết nối, RPO/RTO, thông lượng) và giới hạn (khi nào cách này sai). Câu (trade-off) trả lời theo khung ngữ cảnh → lựa chọn → cái giá → khi nào chọn khác; câu tình huống theo khung cầm máu → khoanh vùng bằng số liệu → sửa gốc → phòng ngừa → bài học cho team.

Thành thật về giới hạn: kiến thức ở đây đủ để trả lời và làm lab, nhưng Senior thật cần trải nghiệm production. Khi chưa có, kể theo dạng "tôi đã tái hiện trong lab với số đo X; ở production tôi sẽ làm thêm Y" — đừng nhận đã vận hành thứ mình chỉ luyện.

Mức ưu tiên: Bắt buộc · Nên biết · Nâng cao. Mỗi câu mở ra có đủ năm phần: ⭐ trả lời ngắn, 📖 giải thích sâu, 💻 code, ⚠️ bẫy, 🔁 câu đào tiếp.

Thuật ngữ mới ở level này

Thuật ngữ Nghĩa ngắn
Happens-before Quy tắc của Java Memory Model bảo đảm một thread thấy thay đổi của thread khác
Pinning (virtual thread) Virtual thread bị giữ chặt vào thread nền, mất lợi ích
Write skew, lost update Bất thường đồng thời khi hai transaction cùng đọc rồi ghi
Dual write, outbox Ghi database và gửi sự kiện riêng rẽ (dễ lệch) / ghi sự kiện cùng transaction rồi chuyển đi
Saga Chuỗi transaction cục bộ có bước bù trừ
Bounded context Ranh giới nghiệp vụ có mô hình riêng (DDD)
p99 Độ trễ mà 99% request nhanh hơn
ADR Bản ghi quyết định kiến trúc

Qua cửa level Senior

  • ○ Mỗi câu tình huống trả lời theo khung, nêu được ít nhất một số đo và một quyết định cầm máu cụ thể.
  • ○ Dự án mini core banking: test đồng thời 0 vi phạm bất biến; outbox không mất sự kiện khi kill ở 5 điểm.
  • ○ Qua 2 buổi mock system design bài ngân hàng; có ADR cho quyết định quan trọng nhất.

Tài liệu học cho level này

Học theo thứ tự:

  1. 💰 Designing Data-Intensive Applications, 2nd edition (2026) — nếu chỉ mua một cuốn, mua cuốn này; không mua bản 2017.
  2. Amazon Builders' Library ✅ — timeout, retry có jitter, API idempotent.
  3. 💰 Fundamentals of Software Architecture, 2nd edition (2025) và 💰 System Design Interview tập 1–2.
  4. martinfowler.com ✅ (Patterns of Distributed Systems) và ADR ✅.
  5. Google SRE books ✅ — SLO, sự cố, postmortem.

Core Java/JVM

  • ○ Bắt buộc JVM trên Kubernetes bị pause dài và OOMKilled — cấu hình bộ nhớ theo container, đọc GC log?Heap theo phần trăm giới hạn container, chừa chỗ cho bộ nhớ ngoài heap; đọc GC log trước khi đổi collector.JVM trên Kubernetes bị pause dài và OOMKilled
  • ○ Bắt buộc volatile đảm bảo điều gì? Happens-before giải thích bằng ví dụ?Đảm bảo nhìn thấy và thứ tự, không đảm bảo nguyên tử — count++ trên volatile vẫn sai.volatile đảm bảo điều gì? Happens-before trong Java Memory Model giải thích bằng ví dụ
  • ○ Bắt buộc Cấu hình thread pool cho đúng — kích thước, hàng đợi, rejection — và virtual thread thay đổi gì? (trade-off)Hàng đợi không giới hạn che quá tải; virtual thread cho I/O chặn, giới hạn tài nguyên bằng semaphore chứ không bằng pool.Cấu hình thread pool thế nào cho đúng
  • ○ Nên biết Virtual thread bên trong — mount/unmount, pinning, ThreadLocal?Từ Java 24 synchronized không còn pin; native call vẫn pin; ThreadLocal tốn bộ nhớ khi có triệu thread.Virtual thread hoạt động bên trong thế nào
  • ○ Nên biết ThreadLocal trong thread pool — rò dữ liệu giữa request, mất ngữ cảnh khi async?Luôn dọn trong finally; truyền ngữ cảnh khi đổi thread; scoped values (Java 25) thay thế.ThreadLocal trong thread pool
  • ○ Nên biết Class loading — ClassNotFoundException vs NoClassDefFoundError?Lỗi thứ hai thường do xung đột phiên bản thư viện hoặc khởi tạo static thất bại.Class loading trong JVM
  • ○ Nâng cao JIT, warm-up và thời gian khởi động — CDS, AOT cache, GraalVM native image?Native image khởi động nhanh, đổi lại thời gian build và hạn chế reflection.JIT, warm-up và thời gian khởi động
  • ○ Nâng cao Structured concurrency giải quyết gì mà CompletableFuture không làm tốt?Huỷ và lỗi theo cây tác vụ; vẫn là preview ở Java 25 — không dùng trong production.Structured concurrency (StructuredTaskScope) giải quyết gì mà CompletableFuture không làm tốt

Data/Transaction

  • ○ Bắt buộc Dirty read, non-repeatable read, phantom, lost update, write skew — mức isolation nào chặn cái nào?PostgreSQL không có dirty read; REPEATABLE READ không chặn write skew; SERIALIZABLE cần retry.Các bất thường đồng thời
  • ○ Bắt buộc Làm việc "sau khi commit" — gửi Kafka, SMS: dual write, @TransactionalEventListener, outbox?Gửi trong transaction có thể gửi mà rollback; gửi sau commit có thể commit mà không gửi — outbox giải quyết.Làm việc "sau khi commit"
  • ○ Bắt buộc Keyset pagination ở tầng JPA/SQL — điều kiện cursor đúng, index phù hợp?Khoá sắp xếp phải duy nhất; index khớp thứ tự và chiều.Keyset pagination ở tầng JPA/SQL

  • ○ Nên biết equals/hashCode cho entity JPA — vì sao khó?Id null trước khi persist; dùng khoá nghiệp vụ bất biến hoặc id với hashCode hằng.equals/hashCode cho entity JPA
  • ○ Nên biết Một service nối hai database (core Oracle + báo cáo PostgreSQL, hoặc primary + replica)?Hai DataSource, hai transaction manager; đọc từ replica phải chịu dữ liệu trễ.Một service nối hai database (core Oracle + báo cáo PostgreSQL, hoặc primary + read replica)
  • ○ Nên biết Xử lý hàng chục triệu dòng bằng JDBC — fetch size, ghi theo lô, COPY?Đọc theo luồng trong transaction; chia theo khoảng khoá để chạy song song và chạy lại được.Xử lý hàng chục triệu dòng bằng JDBC
