Phỏng vấn SQL — Middle

Bộ câu hỏi SQL level Middle — 27 câu lý thuyết và trade-off (window, JSONB, logic trong database, thiết kế schema, index nâng cao, isolation, locking, migration, phân quyền, JPA/Hibernate), 3 câu tình huống, 8 bài thực hành; mỗi câu có trả lời ngắn, giải thích sâu, SQL chạy được, bẫy và câu hỏi đào tiếp.

Level thứ ba trong bộ câu hỏi đi kèm lộ trình SQL từ con số 0 cho dev Frontend — tương ứng giai đoạn 4–8 (tuần 9–22). Trước đó: Newbie · Junior. Sau đó: Senior.

Ở level Middle, câu hỏi chuyển từ "viết được" sang "hiểu cơ chế và biết đánh đổi": vì sao index này không được dùng, vì sao hai request đồng thời làm mất tiền, vì sao JPA bắn 101 câu SQL, nên đặt logic trong database hay ứng dụng. Câu đánh dấu (trade-off) là câu hỏi "tại sao / chọn gì" — trả lời tốt phải có ngữ cảnh, lựa chọn, cái giá và khi nào chọn khác. Câu tình huống trả lời theo khung: đo → khoanh vùng → giảm đau ngay → sửa gốc → kiểm chứng → phòng ngừa.

Mỗi câu mở ra có đủ năm phần: ⭐ trả lời ngắn, 📖 giải thích sâu, 💻 SQL/Java chạy được, ⚠️ bẫy, 🔁 câu đào tiếp. Dòng in nghiêng là ý chính để ôn nhanh.

Thuật ngữ mới ở level này

Thuật ngữ Nghĩa ngắn
Frame (window) Phạm vi dòng hàm window nhìn thấy — ROWS theo số dòng, RANGE theo giá trị
Execution plan Cách database thực thi câu SQL — xem bằng EXPLAIN (ANALYZE, BUFFERS)
Index-only scan Đọc dữ liệu ngay từ index, không cần đọc bảng
Isolation level Mức các transaction đồng thời thấy thay đổi của nhau
Lost update / write skew Hai transaction cùng đọc rồi ghi, một bên mất thay đổi / cùng nhau phá một điều kiện
Optimistic / pessimistic lock Kiểm tra xung đột khi ghi (cột version) / khoá khi đọc (FOR UPDATE)
Persistence context Bộ nhớ đệm entity của JPA trong một transaction; sửa field là có UPDATE
N+1 Một truy vấn danh sách kéo theo N truy vấn chi tiết
Migration Thay đổi schema có phiên bản, áp theo thứ tự (Flyway, Liquibase)

Qua cửa level Middle

  • ○ Bảng số đo trước/sau cho ≥ 5 truy vấn trong lab index; giải thích từng plan.
  • ○ Tái hiện và sửa lost update, write skew, deadlock bằng hai phiên psql.
  • ○ Test đếm query đỏ khi có N+1 và xanh sau khi sửa.
  • ○ Trả lời 6 câu (trade-off) theo khung: ngữ cảnh → lựa chọn → cái giá → khi nào chọn khác.

Tài liệu học cho level này

Học theo thứ tự:

  1. Use The Index, Luke! ✅ — đọc hết, bắt buộc.
  2. PostgreSQL — Using EXPLAIN ✅ và Concurrency Control ✅.
  3. PostgreSQL 14 Internals ✅ — sách PDF miễn phí: MVCC, locks, thực thi truy vấn, các loại index.
  4. explain.dalibo.com ✅ — đọc plan dạng cây.
  5. strong_migrations ✅ — thao tác schema nguy hiểm và cách làm an toàn.

Làm ngân hàng: thêm Oracle Database documentation ✅ (Concepts) và Oracle Dev Gym ✅. Danh sách đầy đủ: Tài liệu SQL theo level — Middle.

SQL nâng cao

  • ○ Window function: PARTITION BY, ORDER BY, frame ROWS vs RANGE; luỹ kế, trung bình trượt, LAG/LEAD?Frame mặc định khi có ORDER BY là RANGE … CURRENT ROW — dòng trùng giá trị được cộng cùng lúc.Window function
  • ○ Cột JSON/JSONB khi nào dùng, khi nào phải tách bảng; index GIN? (trade-off)Hợp phần thật sự linh hoạt hoặc payload gốc; không thay cột cho dữ liệu cần ràng buộc, JOIN, thống kê.Cột JSON/JSONB trong PostgreSQL
  • ○ View và materialized view; làm mới thế nào, CONCURRENTLY?View là truy vấn có tên; materialized view lưu kết quả, phải refresh, CONCURRENTLY cần unique index.View và materialized view
  • ○ Stored procedure, function, trigger; logic nghiệp vụ nên ở database hay ứng dụng? (trade-off)Database giữ bất biến dữ liệu; quy tắc nghiệp vụ thay đổi thường xuyên để ở ứng dụng cho dễ test, dễ deploy.Function, stored procedure, trigger
  • ○ Tìm kiếm văn bản: vì sao LIKE '%abc' không dùng index; pg_trgm, full-text, unaccent?B-tree chỉ tìm được theo tiền tố; trigram cho tìm chuỗi con; full-text cho tìm theo từ.Tìm kiếm văn bản trong database

Thiết kế dữ liệu

  • ○ Thiết kế schema cho hệ thống giao dịch từ nghiệp vụ tới ERD tới bảng; bất biến nào thành ràng buộc?Mọi bất biến diễn đạt được thì thành ràng buộc; quan hệ n-n có thuộc tính; sổ cái kép.Thiết kế schema cho hệ thống giao dịch
  • ○ Khoá tự nhiên hay khoá đại diện; bigint tự tăng, UUID v4, UUID v7? (trade-off)UUID v4 ngẫu nhiên làm index phân mảnh; UUID v7 sắp theo thời gian; bigint nhỏ, nhanh nhưng lộ thứ tự.Chọn khoá chính cho bảng giao dịch
  • ○ Lưu cây phân cấp: adjacency list, ltree, nested set, closure table? (trade-off)Adjacency list dễ ghi, đọc cần đệ quy; closure/ltree đọc nhanh, cập nhật phức tạp hơn.Lưu cấu trúc cây trong database
  • ○ Soft delete và audit log ở tầng database; so với làm ở JPA hoặc CDC? (trade-off)Partial unique index; trigger bắt mọi đường ghi; biến phiên cho "ai sửa"; bảo vệ bảng audit.Soft delete và audit log ở tầng database

Index và hiệu năng

  • ○ Clustered (InnoDB) vs heap (PostgreSQL); index cho khoá ngoại; index-only scan; index thừa?InnoDB sắp bảng theo PK; PostgreSQL không tự index FK; tìm index không dùng bằng pg_stat_user_indexes.Index nâng cao và bảo trì
  • ○ Vì sao OFFSET chậm; keyset pagination viết thế nào cho đúng?OFFSET đọc rồi bỏ; keyset WHERE (created_at, id) < (…) với index khớp thứ tự.Keyset pagination ở tầng JPA/SQL
  • ○ Tìm nguyên nhân database chậm: pg_stat_statements, pg_stat_activity, wait event, chuỗi chặn khoá?Tìm truy vấn tốn nhất theo tổng thời gian trước; phân biệt chậm do CPU/IO với chậm do chờ khoá.Theo dõi database để tìm nguyên nhân chậm

Transaction và đồng thời

  • ○ Dirty read, non-repeatable read, phantom, lost update, write skew — mức isolation nào chặn cái nào?PostgreSQL không có dirty read; REPEATABLE READ chặn phantom nhưng không chặn write skew; SERIALIZABLE cần retry.Các bất thường đồng thời
  • ○ Optimistic vs pessimistic locking và cập nhật nguyên tử — chọn gì cho số dư, hồ sơ, giữ chỗ? (trade-off)Xung đột hiếm → @Version; xung đột nhiều, làm lại đắt → FOR UPDATE; số dư → UPDATE … SET balance = balance - x WHERE balance >= x.Optimistic vs pessimistic locking và cập nhật nguyên tử

Vận hành

  • ○ Flyway hay Liquibase; versioned vs repeatable; vì sao không sửa migration đã chạy?Checksum đảm bảo mọi môi trường giống nhau; sửa thì tạo migration mới.Quản lý schema bằng Flyway hoặc Liquibase
  • ○ Phân quyền database theo quyền tối thiểu; owner, migration, ứng dụng, chỉ đọc; Row-Level Security?Ứng dụng không có DDL; default privileges cho bảng mới; RLS cho phân quyền theo dòng.Phân quyền trong database

Kết hợp với JPA và Spring

  • ○ N+1 trong JPA: phát hiện bằng số đo, sửa bằng fetch join, entity graph, batch fetching?Test đếm query; JOIN FETCH với collection không phân trang được trong SQL — cẩn thận.N+1 query trong JPA/Hibernate
  • ○ LazyInitializationException và Open Session in View — có nên tắt, sửa thế nào? (trade-off)OSIV giữ connection suốt request; tắt và lấy đủ dữ liệu trong service (fetch join, DTO).LazyInitializationException và Open Session in View
  • ○ Persistence context, trạng thái entity, dirty checking — vì sao sửa field là có UPDATE?Entity managed được so với bản chụp khi flush; không cần gọi save().Persistence context, trạng thái entity và dirty checking
  • ○ @Transactional hoạt động thế nào; vì sao gọi nội bộ thì mất transaction?Proxy bọc bean; this.method() không đi qua proxy; transaction gắn với thread.@Transactional hoạt động thế nào
  • ○ Khi nào transaction rollback: checked vs unchecked, rollbackFor, bắt exception rồi đi tiếp?Mặc định chỉ rollback với unchecked; nuốt exception thì commit; UnexpectedRollbackException.Khi nào transaction rollback
  • ○ IDENTITY hay SEQUENCE (allocationSize); vì sao IDENTITY tắt batch insert? (trade-off)Hibernate cần id trước khi insert để gom lô; IDENTITY chỉ có id sau khi insert.Chiến lược sinh khoá chính
  • ○ JdbcTemplate/JdbcClient hay JPA — khi nào chọn JDBC? (trade-off)Báo cáo, truy vấn phức tạp, ghi khối lớn → JDBC; nghiệp vụ trên aggregate → JPA.JdbcTemplate, NamedParameterJdbcTemplate và JdbcClient
  • ○ Oracle mà dev Java phải biết khi vào ngân hàng: phân trang, sequence, '' = NULL, DATE có giờ?Code cũ dùng ROWNUM; DATE so bằng bỏ sót giờ; package PL/SQL gọi bằng SimpleJdbcCall.Oracle mà dev Java phải biết khi vào ngân hàng
  • ○ MyBatis so với JPA; #{} vs ${}?#{} là tham số bind an toàn; ${} ghép chuỗi — chỉ dùng với giá trị đã whitelist.MyBatis so với JPA

Mở rộng

  • ○ Redis dùng vào việc gì trong hệ thống Spring Boot; kiểu dữ liệu nào cho việc nào?Cache, phiên, rate limit, bảng xếp hạng; không phải nguồn sự thật cho số dư.Redis trong hệ thống Spring Boot
  • ○ Chọn database quan hệ, document, key-value, wide-column, tìm kiếm thế nào? (trade-off)Theo mẫu truy cập, yêu cầu nhất quán và năng lực vận hành; PostgreSQL là mặc định hợp lý.Chọn database

Câu tình huống

  • ○ Màn sao kê trang 1 nhanh, trang 5.000 mất 6 giây, cuộn còn thấy giao dịch lặp — xử lý thế nào?OFFSET đọc rồi bỏ và trượt khi có dữ liệu mới; chuyển keyset + cursor, đổi hợp đồng API với FE.Tình huống: màn sao kê trang 1 mở trong 50 ms, trang 5.000 mất 6 giây, khi cuộn còn thấy giao dịch lặp
  • ○ Lỡ chạy UPDATE thiếu WHERE trên production, 2,3 triệu khách bị ghi đè — làm gì theo thứ tự nào?Dừng, báo, khoanh thời điểm; khôi phục PITR sang máy tạm; vá đúng cột; rút kinh nghiệm quy trình.Tình huống: lỡ chạy UPDATE thiếu WHERE trên production
  • ○ Endpoint danh sách hồ sơ chạy 101 truy vấn — sửa còn ≤ 2 mà không phá phân trang?Viết test đếm query trước; phân trang id trước rồi fetch theo lô; DTO projection.Bài tập: endpoint danh sách hồ sơ vay chạy 101 truy vấn
