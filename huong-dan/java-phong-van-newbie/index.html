Phỏng vấn Java Spring Boot — Newbie

31 câu lý thuyết cho người mới vào Java (Core Java, Spring Boot mở đầu, REST, test, Git, kỹ năng mềm) và 4 bài thực hành có lời giải chạy được; mỗi câu có mức ưu tiên, trả lời ngắn để nói, giải thích sâu, code, bẫy và câu hỏi đào tiếp.

Level đầu tiên của bộ câu hỏi đi kèm lộ trình Java Spring Boot từ con số 0 — tương ứng giai đoạn 1–2 (khoảng tháng 1–3). Level sau: Junior · Middle · Senior.

Mỗi câu mở ra có đủ năm phần: ⭐ trả lời ngắn (đoạn nói trong 45 giây), 📖 giải thích sâu (cơ chế, vì sao), 💻 code chạy được, ⚠️ bẫy hay gặp, 🔁 câu hỏi đào tiếp. Dòng in nghiêng dưới mỗi câu là ý chính để ôn nhanh. Mở câu, tự trả lời thành tiếng trước rồi mới xem đáp án.

Mức ưu tiên: Bắt buộc phải trả lời trôi · Nên biết hay bị hỏi, trả lời được là điểm cộng · Nâng cao dành cho người muốn nổi bật.

Ở level này người phỏng vấn kiểm tra bạn viết Java đúng kiểu Java và hiểu những thứ nền tảng: kiểu dữ liệu, OOP, collection, exception, stream. Với ứng viên từ Frontend, họ thường hỏi thêm "Java khác TypeScript ở đâu" — câu đầu tiên dưới đây.

Qua cửa level Newbie

  • ○ Trả lời thành tiếng mọi câu Bắt buộc, mỗi câu ≤ 1 phút, không nhìn đáp án.
  • ○ Làm 4 bài thực hành, có test, không chép lời giải.
  • ○ Giải 6/8 bài live coding collections, mỗi bài ≤ 20 phút.

Tài liệu học cho level này

Học theo thứ tự, xong cái trước mới sang cái sau:

  1. dev.java — Learn ✅ — tài liệu chính thức: Language Basics → Classes and Objects → Exceptions → Generics → Collections → Lambda và Stream.
  2. MOOC.fi — Java Programming I và II ✅ — hàng trăm bài tập chấm tự động; Programming I trong tháng 1, II trong tháng 2–3.
  3. Exercism — Java track ✅ — 20 bài đầu, có mentor review.
  4. JUnit User Guide ✅ — JUnit 6 là bản đi cùng Spring Boot 4; cách viết test giống JUnit 5.

Sách nên mua nếu có ngân sách: 💰 Head First Java, 3rd edition. Danh sách đầy đủ, phần cần đọc, tài liệu đã cũ cần tránh: Tài liệu Java theo level — Newbie.

Core Java

  • ○ Bắt buộc Bạn từ TypeScript sang — Java khác ở đâu, những lỗi nào dễ mắc?Kiểu được kiểm tra cả lúc chạy, nominal typing, int/long/BigDecimal thay number, chỉ có null, equals cho object.Từ TypeScript sang Java
  • ○ Bắt buộc JDK, JRE, JVM khác nhau thế nào? Từ file .java tới lúc chạy đi qua những bước nào?javac biên dịch ra bytecode, JVM nạp và chạy, JIT dịch phần nóng sang mã máy; JDK là JRE cộng công cụ phát triển.JDK, JRE và JVM khác nhau thế nào? Từ file .java tới lúc chạy
  • ○ Bắt buộc Maven làm gì — pom.xml, lifecycle, dependency scope, BOM?Giống package.json + script của npm; scope test/provided; Spring Boot dùng BOM để cố định phiên bản thư viện.Maven cho người mới vào dự án Java
  • ○ Bắt buộc 8 kiểu nguyên thuỷ, ép kiểu, tràn số và chia nguyên?int tràn không báo lỗi; số lớn dùng long; ép thu hẹp làm mất dữ liệu; 7 / 2 ra 3.8 kiểu nguyên thuỷ, ép kiểu mở rộng/thu hẹp, tràn số và chia nguyên
  • ○ Bắt buộc Vì sao String bất biến? == khác equals thế nào? Khi nào dùng StringBuilder?== so tham chiếu, equals so nội dung; nối chuỗi trong vòng lặp dùng StringBuilder.Vì sao String là immutable? == và equals khác gì? StringBuilder, string pool và nối chuỗi trong vòng lặp
  • ○ Bắt buộc Java truyền tham trị hay tham chiếu?Luôn tham trị — với object là sao chép tham chiếu: sửa object thì bên ngoài thấy, gán lại biến thì không.Java truyền tham trị hay tham chiếu? Giải thích bằng ví dụ sửa object và gán lại biến bên trong method
  • ○ Nên biết public, protected, package-private, private — phạm vi từng cái?Mặc định không ghi gì là package-private, khác TS mặc định public; dùng để giấu chi tiết trong package.public, protected, package-private, private
  • ○ Bắt buộc final, static, finally, finalize — mỗi từ khoá làm gì?final khoá biến chứ không làm object bất biến; field static có thể thay đổi trong bean là nguy hiểm; finalize đã lỗi thời.final, static, finally và finalize
  • ○ Nên biết Constructor, this() và super(), thứ tự khởi tạo static, field, constructor?Khối static chạy một lần khi nạp class; constructor lớp cha chạy trước lớp con.Constructor trong Java
  • ○ Bắt buộc Bốn tính chất OOP và nguyên tắc SOLID — ví dụ trong ứng dụng ngân hàng?Đóng gói, kế thừa, đa hình, trừu tượng; SOLID giúp thay đổi biểu phí, kênh thanh toán mà không sửa code cũ.Bốn tính chất OOP và nguyên tắc SOLID
  • ○ Bắt buộc Interface và abstract class khác nhau thế nào từ Java 8 trở đi?Interface có default method nhưng không giữ trạng thái; abstract class có field và constructor; một class implements nhiều interface.Interface và abstract class khác nhau thế nào từ Java 8 trở đi
  • ○ Bắt buộc Overloading và overriding khác nhau thế nào?Overload chọn lúc biên dịch theo kiểu tham số; override chọn lúc chạy theo kiểu thật của object.Overloading và overriding khác nhau thế nào
  • ○ Bắt buộc Vì sao override equals() thì phải override hashCode()?HashMap/HashSet tìm theo hashCode rồi mới equals; sai một trong hai là "mất" phần tử; record tự sinh đúng.Vì sao override equals() thì phải override hashCode()? Record giải quyết thế nào, và bẫy với entity JPA?
  • ○ Nên biết Vì sao Integer a = 127, b = 127 thì a == b đúng mà với 128 lại sai?Cache Integer từ −128 tới 127; so Integer bằng equals; unboxing null ném NPE.Vì sao Integer a = 127, b = 127 thì a == b là true nhưng với 128 lại false
  • ○ Bắt buộc Checked và unchecked exception khác nhau thế nào? Thiết kế xử lý lỗi cho ứng dụng Spring?Checked buộc khai báo; lỗi nghiệp vụ thường là unchecked có kiểu riêng, bắt tập trung ở tầng API.Checked và unchecked exception khác nhau thế nào? Thiết kế xử lý lỗi cho ứng dụng Spring Boot ra sao?
  • ○ Bắt buộc Chọn collection thế nào — ArrayList vs LinkedList, HashMap vs LinkedHashMap vs TreeMap?Mặc định ArrayList và HashMap; cần thứ tự chèn dùng LinkedHashMap, cần sắp xếp dùng TreeMap.Chọn collection thế nào
  • ○ Nên biết List.of, Collections.unmodifiableList, Arrays.asList, Stream.toList khác nhau thế nào?Bất biến thật hay chỉ là "khung nhìn" không cho sửa; List.of không nhận null.List.of, Collections.unmodifiableList, Arrays.asList, List.copyOf và Stream.toList khác nhau thế nào

  • ○ Bắt buộc Lambda, functional interface và method reference?Function, Supplier, Consumer, Predicate; lambda chỉ dùng biến cục bộ "effectively final".Lambda, functional interface và method reference
  • ○ Bắt buộc Stream API hoạt động thế nào — lazy, intermediate, terminal; khi nào không nên dùng?Không có thao tác terminal thì không chạy; stream chỉ dùng một lần; vòng lặp đơn giản có khi dễ đọc hơn.Stream API hoạt động thế nào
  • ○ Bắt buộc Optional dùng đúng cách thế nào, chỗ nào không nên dùng?Cho kiểu trả về "có thể không có"; không dùng cho field, tham số, collection; orElseThrow với lỗi nghiệp vụ.Optional dùng đúng cách thế nào
  • ○ Bắt buộc Xử lý tiền tệ — vì sao không dùng double, BigDecimal dùng thế nào cho đúng?Tạo từ chuỗi, so bằng compareTo, làm tròn có chủ đích bằng RoundingMode.Xử lý tiền tệ trong Java
  • ○ Nên biết LocalDate, LocalDateTime, Instant, ZonedDateTime, OffsetDateTime — chọn kiểu nào?Thời điểm giao dịch dùng Instant/OffsetDateTime; ngày hiệu lực hợp đồng dùng LocalDate.LocalDate, LocalDateTime, Instant, ZonedDateTime, OffsetDateTime
  • ○ Bắt buộc Annotation trong Java khác decorator trong Angular thế nào?Annotation chỉ là dữ liệu mô tả; Spring đọc rồi tạo proxy; gọi nội bộ qua this bỏ qua proxy.Annotation trong Java khác decorator trong TypeScript/Angular thế nào
