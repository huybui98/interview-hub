Phỏng vấn SQL — Newbie

Bộ câu hỏi SQL cho người chưa từng làm database — 16 câu lý thuyết, 5 bài thực hành có dữ liệu mẫu tự chạy, 1 dự án; mỗi câu có trả lời ngắn để nói, giải thích sâu, SQL chạy được trên PostgreSQL, bẫy và câu hỏi đào tiếp.

Đây là level đầu tiên trong bộ câu hỏi đi kèm lộ trình SQL từ con số 0 cho dev Frontend — tương ứng giai đoạn 1–2 (tuần 1–5). Level sau: Junior · Middle · Senior.

Mỗi câu mở ra có đủ năm phần: ⭐ trả lời ngắn (đoạn nói trong 45 giây khi phỏng vấn), 📖 giải thích sâu (cơ chế, vì sao), 💻 SQL chạy được trên PostgreSQL 18, ⚠️ bẫy hay gặp, 🔁 câu hỏi đào tiếp mà người phỏng vấn thường hỏi. Bài thực hành có thêm đề, gợi ý mở dần, dữ liệu mẫu dạng CREATE TABLE/INSERT và lời giải có số dòng mong đợi.

Cách học: mở câu, tự trả lời thành tiếng trước rồi mới xem đáp án, chấm điểm để app nhắc ôn lại câu chưa chắc. Dòng in nghiêng dưới mỗi câu là ý chính để ôn nhanh — không thay được việc mở câu đầy đủ.

Thuật ngữ cần biết trước

Thuật ngữ Nghĩa ngắn So với Frontend
Database / DBMS Tập dữ liệu có tổ chức / phần mềm quản lý nó (PostgreSQL, Oracle…) Backend lưu trữ thay cho localStorage
Table, row, column Bảng, dòng (bản ghi), cột (thuộc tính có kiểu cố định) Mảng object cùng interface
Schema Không gian tên chứa bảng; cũng có nghĩa là cấu trúc bảng Một library/module
Primary key (PK) Cột định danh duy nhất, không NULL track item.id
Foreign key (FK) Cột trỏ tới PK của bảng khác, database kiểm tra tồn tại Id tham chiếu trong state chuẩn hoá
Constraint Quy tắc database kiểm tra ở mọi lần ghi Validator — nhưng không bỏ qua được
NULL "Không biết" — không bằng gì, kể cả NULL Khác null của JS
Query Câu SQL đọc hoặc ghi dữ liệu Lời gọi API
DDL / DML Lệnh đổi cấu trúc / lệnh đổi dữ liệu Sửa interface / sửa dữ liệu

Qua cửa level Newbie

  • ○ Trả lời thành tiếng 16 câu lý thuyết dưới đây, mỗi câu ≤ 1 phút, không nhìn đáp án.
  • ○ Làm 5 bài thực hành, đoán đúng số dòng kết quả trước khi chạy ở ≥ 80% câu.
  • ○ Dự án mini-bank v0 chạy được trên máy người khác trong ≤ 5 phút.
  • ○ Giải thích được 3 bẫy: = NULL, NOT IN gặp NULL, count(*) sau LEFT JOIN.

Tài liệu học cho level này

Học theo thứ tự:

  1. SQLBolt ✅ — bài tập trên trình duyệt, xong trong tuần 1.
  2. PostgreSQL Tutorial ✅ — 3 chương chính thức, ngắn.
  3. PostgreSQL Exercises ✅ — Simple SQL Queries → Joins and Subqueries → Modifying Data.
  4. Select Star SQL ✅ — sách tương tác dạy cách nghĩ.
  5. PostgreSQL Wiki — Don't Do This ✅ — tránh thói quen xấu từ đầu.

Sách nên mua: 💰 Practical SQL, 2nd edition (2022, viết cho PostgreSQL). Danh sách đầy đủ: Tài liệu SQL theo level — Newbie.

Cơ bản

  • ○ Database quan hệ là gì? Sao không lưu JSON trong file cho nhanh?Bảng–dòng–cột–khoá; DBMS cho ràng buộc, transaction, đồng thời, index — file JSON không có.Database quan hệ là gì
  • ○ Cluster, database, schema, table trong PostgreSQL khác nhau thế nào? "Schema" ở MySQL, Oracle có giống không?Connection gắn một database; schema là namespace; MySQL: database = schema; Oracle: schema = user.Cluster, database, schema, table trong PostgreSQL khác nhau thế nào
  • ○ SQL là ngôn ngữ khai báo nghĩa là gì? DDL, DML, DCL, TCL gồm lệnh nào?Mô tả kết quả, planner chọn cách làm; PostgreSQL rollback được DDL, Oracle/MySQL tự commit.SQL là ngôn ngữ khai báo
  • ○ Các kiểu dữ liệu hay dùng; vì sao tiền dùng numeric chứ không float; timestamp khác timestamptz?numeric chính xác tuyệt đối; timestamptz lưu thời điểm UTC, timestamp chỉ là giờ treo tường.Kiểu dữ liệu trong SQL
  • ○ PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, NOT NULL, DEFAULT; ON DELETE CASCADE dùng khi nào?Ràng buộc là luật của dữ liệu; CASCADE nguy hiểm với dữ liệu tài chính; PostgreSQL không tự index FK.Ràng buộc và sinh khoá
  • ○ Viết SELECT … WHERE với AND/OR, IN, BETWEEN, LIKE; bẫy nào hay gặp?AND ưu tiên hơn OR; BETWEEN gồm hai đầu; LIKE phân biệt hoa thường ở PostgreSQL.SELECT … WHERE
  • ○ ORDER BY, LIMIT/OFFSET, DISTINCT; vì sao phân trang bị trùng hoặc mất dòng?Bảng không có thứ tự; sắp xếp phải toàn phần (thêm id); DISTINCT không chữa được.ORDER BY, LIMIT/OFFSET và DISTINCT
  • ○ NULL ảnh hưởng thế nào tới so sánh, COUNT/SUM/AVG, NOT IN?Logic ba giá trị; WHERE chỉ giữ TRUE; hàm tổng hợp bỏ qua NULL; NOT IN + NULL = rỗng.NULL trong SQL
  • ○ INSERT, UPDATE, DELETE cơ bản; RETURNING; làm sao không lỡ tay sửa cả bảng?Đếm trước bằng đúng WHERE → BEGIN → so số dòng bị ảnh hưởng → COMMIT/ROLLBACK.INSERT, UPDATE, DELETE cơ bản
  • ○ DELETE, TRUNCATE, DROP khác nhau thế nào? Lệnh nào rollback được?Xoá dòng / xoá sạch dữ liệu / xoá cả bảng; PostgreSQL rollback được cả ba, Oracle/MySQL thì không với TRUNCATE và DROP.DELETE, TRUNCATE, DROP khác nhau thế nào
  • ○ Những chỗ SQL khác JavaScript khiến dev Frontend viết sai?Nháy đơn/kép, chia số nguyên, NULL, tên chữ hoa, || NULL, tháng bắt đầu từ 1.Những chỗ SQL khác JavaScript khiến dev Frontend viết sai

JOIN và quan hệ

  • ○ INNER JOIN và LEFT JOIN khác nhau thế nào? WHERE khác HAVING?LEFT giữ mọi dòng trái; điều kiện bảng phải đặt trong ON, đặt trong WHERE là thành INNER.INNER JOIN vs LEFT JOIN, WHERE vs HAVING
  • ○ Quan hệ 1-1, 1-n, n-n biểu diễn bằng bảng thế nào? Sao không lưu "1,2,3" trong một cột?FK ở phía nhiều; n-n cần bảng trung gian có thể mang thuộc tính; 1-1 cần UNIQUE.Quan hệ 1-1, 1-n, n-n biểu diễn bằng bảng thế nào

Aggregate

  • ○ GROUP BY và hàm tổng hợp; vì sao cột trong SELECT phải nằm trong GROUP BY?Mỗi nhóm ra một dòng; WHERE lọc dòng trước, HAVING lọc nhóm sau; SUM tập rỗng là NULL.GROUP BY và hàm tổng hợp cơ bản

Index và transaction (mức khái niệm)

  • ○ Index là gì, vì sao làm đọc nhanh mà ghi chậm? Có nên index mọi cột?Như mục lục sách; mỗi lần ghi phải cập nhật mọi index; chọn theo truy vấn thật.Index hoạt động thế nào
  • ○ Transaction là gì? Giải thích ACID bằng một lệnh chuyển tiền.Hai bút toán cùng thành công hoặc cùng huỷ; isolation có nhiều mức — học kỹ ở level sau.Transaction và ACID giải thích bằng một lệnh chuyển tiền

Bài thực hành

Bộ dữ liệu dùng chung nằm trong bài 2 — chạy phần chuẩn bị một lần, các bài sau dùng lại.

  • ○ Bài 1 — Tạo bảng có đủ ràng buộc, rồi vi phạm từng ràng buộc và đọc mã SQLSTATEBài tập: tạo bảng khách hàng và tài khoản có đủ ràng buộc
  • ○ Bài 2 — 10 câu lọc và sắp xếp: ranh giới tháng, NULL, ILIKE, phân trang toàn phầnBài tập: 10 câu lọc và sắp xếp đầu tiên trên dữ liệu khách hàng
  • ○ Bài 3 — Thống kê tài khoản: GROUP BY, HAVING, tỉ lệ phần trăm không chia nguyênBài tập: thống kê tài khoản
  • ○ Bài 4 — JOIN đầu tiên: khách chưa có tài khoản, đếm kể cả 0, điều kiện đặt sai chỗBài tập: những câu JOIN đầu tiên
  • ○ Bài 5 — Sửa và xoá an toàn trong transaction, cứu một UPDATE quên WHEREBài tập: sửa và xoá dữ liệu an toàn
  • ○ Dự án — mini-bank v0: Docker, schema, seed chạy lại được, 15 truy vấn nghiệp vụDự án: mini-bank v0
